# ttalkkak 개선 계획

## 목표

한글 입력 판정과 문장 전환을 안정화하고, 현재 입력 중인 글자에 밑줄을 표시하며 오타·진행 상황을 더 쉽게 알아보도록 한다.

## 단계

1. **문장 로딩과 이동** (`src/App.jsx`): 문장 목록을 한 번만 가져와 보관한다. 로딩·오류·문장 수 0~1개를 처리하고, 처음/이전/다음 이동을 검증한다.
2. **한글 판정** (`src/typing.js`, `src/typing.test.js`): 조합 중인 글자는 입력된 자모만 비교하고 조합이 끝난 글자는 전체 자모를 비교한다. 마지막 받침 누락, 초과 입력, 빈 입력을 검증한다. 표시와 정확도·최고 기록에 같은 판정을 사용한다.
3. **입력 피드백** (`src/App.jsx`, `src/App.css`): 빈 입력은 첫 글자, 입력 중에는 커서 바로 앞 글자에 짧은 밑줄을 표시한다. 오타는 글자색과 배경을 함께 사용한다. 백스페이스·중간 수정·한글 조합·문장 전환을 확인한다.
4. **화면과 접근성** (`src/App.jsx`, `src/App.css`): 문장 진행 막대를 추가하되 입력창의 기존 포커스 스타일과 간결한 문구 구성을 유지한다. 모바일에서 문장·입력창·통계가 읽히는지 확인한다. 선택 메뉴와 최고 기록 초기화의 키보드 접근을 보완한다.
5. **배포와 품질** (`index.html`, `eslint.config.js`): Vite의 `/ttalkkak/` 경로에서 매니페스트와 파비콘이 열리도록 맞추고, 린트 오류를 해결한다. `pnpm test`, `pnpm lint`, `pnpm build` 및 브라우저 동작을 확인한다.

## 밑줄 동작 기준

| 입력 | 밑줄 |
| --- | --- |
| 비어 있음 | 첫 글자 |
| `작은`을 입력하며 `작`까지 입력 | `작` |
| `은`을 입력하기 시작 | `은` |
| 오타 입력 | 오타 배경과 같은 글자의 밑줄 |
| 새 문장으로 이동 | 새 문장의 첫 글자 |

완료 전에는 마지막 글자를 수정할 수 있으므로 밑줄을 유지하고, 문장을 전환하면 초기화한다.

## 후속: 한글 조합과 Space 전환

1. `가나`를 입력할 때 IME가 잠시 `간`으로 표시하는 경우를 자모 판정 테스트로 재현한다. 조합 중에만 다음 글자의 첫 자음과 일치하는 임시 받침을 허용하고, 조합이 끝난 `간`은 오타로 판정한다.
2. 문장 전체 입력 후 Space가 조합 확정과 함께 눌려도, 키를 놓을 때 확정된 입력값으로 문장을 전환한다. 전환용 공백은 점수에 포함하지 않는다. Enter와 미완성 문장의 Space 동작은 유지한다.
3. 자모·입력 정규화 테스트를 먼저 실패시킨 뒤 최소 수정으로 통과시키고, 브라우저의 일반 Space/Enter 흐름과 `pnpm test`, `pnpm lint`, `pnpm build`를 확인한다.
